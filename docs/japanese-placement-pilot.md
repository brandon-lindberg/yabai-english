## Versioned collection forms

`createJapanesePilotForms` partitions the current private schema-v4 bank into **twenty fixed forms: ten with 24 items and ten with 23**. Together they cover all 470 item IDs/revisions exactly once; each form includes all six domains. Questions sharing a reading passage appear on different forms. Each participant takes one form, so neither skips nor a second session can expose a sibling question to that participant within a collection.

The allocator respects capacity and passage groups, spreads domain/reference-band strata across forms and rotates the starting domain in the displayed order. It is deterministic. These are collection forms, not adaptive paths, equivalent test forms or a validated sampling design. Their domain mix differs from the production quotas, and source bands remain authoring labels. Timing and performance on these forms alone cannot validate a production adaptive path.

The form manifest binds the complete bank snapshot, item revisions, form revisions, ordered item references, twenty-minute limit and maximum 24-item budget. Its digest also binds the partition and item order. For the current catalog:

- Bank digest: `33ed9d52018f5a2d4cd615fbe2cfa3472fc303112eb6c2076c37516c52e40037`.
- Forms digest: `ad8ca2f0ae0d0caddb18e3767cb101d62668e87bd0e42fb33e4504c333761d4c`.

Retain the exact manifest alongside the exact private bank snapshot for a study. Reordering a form changes its digest; editing bank content or parameters requires a new bound manifest. Existing responses cannot silently attach to the new version. The CLI intentionally reads the current checked-in catalog and rejects an older manifest after catalog drift; analyzing an older collection requires its matching catalog revision and manifest.

The learner export uses the same explicit question projection as production. It includes the form digest, item revisions, visible questions and public source notices; it excludes answer keys, accepted orders, explanations, private permission evidence, passage grouping and difficulty fields. `awardsLevel: false` and `mode: offline_static_pilot` identify its scope. A collection runner must retain source notices and the full applicable files in `apps/web/data/japanese-placement/licences/`, plus referenced attribution/change notices. The JSON export is not a licence-file bundler or authorization to distribute the drafts.

## Commands

Run from the repository root. These commands read local files and write JSON to stdout. They do not load credentials, call the database, fetch sources, publish a bank or overwrite files. Use absolute paths for input/output files because the root script runs in `apps/web`.

```sh
# The silent flag keeps Yarn progress text out of redirected JSON.
yarn --silent japanese-placement:pilot forms > /private/tmp/japanese-pilot-forms.json
yarn --silent japanese-placement:pilot form \
  --forms /private/tmp/japanese-pilot-forms.json --id form-001 \
  > /private/tmp/japanese-pilot-form-001.json

# Supply actual collected data; this file is not generated by the command.
yarn --silent japanese-placement:pilot diagnose \
  --forms /private/tmp/japanese-pilot-forms.json \
  --data /absolute/private/study-observations.json \
  > /absolute/private/study-diagnostics.json
```

`forms`, `form` and `diagnose` are mutually exclusive commands. Unknown, missing and repeated arguments fail with exit code 1. Invalid files produce no partial JSON report. Schema errors do not echo participant-supplied values to terminal logs. Diagnostics files are analyst artifacts containing answer-pattern counts, not learner exports.

## Observation contract

The strict runtime schemas and exported TypeScript types live in `apps/web/src/lib/japanese-placement/pilot.ts`. A collection envelope has this shape; substitute the actual forms digest, study UUID and SHA-256 digest of the study protocol:

```json
{
  "schemaVersion": 1,
  "kind": "japanese-pilot-observations",
  "formsDigest": "ad8ca2f0ae0d0caddb18e3767cb101d62668e87bd0e42fb33e4504c333761d4c",
  "studyId": "00000000-0000-4000-8000-000000000001",
  "protocolDigest": "<64 lowercase hexadecimal characters from the actual protocol>",
  "participants": []
}
```

An empty collection is valid and reports no evidence. The sample study UUID is a placeholder, not a registered study or learner record. No synthetic participant data is stored as real evidence.

Each participant supplies:

- `id`: a study-specific opaque UUID; `split`: `development` or `holdout`. Assign the split by person before fitting, according to the study protocol.
- `reference`: `band` (`BELOW_N5`, `N5`–`N1`), `method` (`jlpt` or `independent_japanese_reading_writing`), `assessedOn` (valid `YYYY-MM-DD`) and `evidenceId` (opaque UUID). JLPT cannot label a below-N5 award. The protocol must define independently established Japanese reference criteria; an English result, source tag, self-selected band or this pilot's own score is not a reference method.
- `session`: unique UUID `id`, manifest `formId`, integer `elapsedMs` within 0–1,200,000, `endedBy` (`completed`, `time_limit` or `withdrawn`) and ordered `observations`.

Each observation supplies `itemId`, `itemRevision`, one-based `position`, integer `presentedAtMs`, nullable `submittedAtMs` and nullable `response`. Times are offsets from session start. A response reuses the production input contract:

- Choice: `{ "kind": "answer", "itemId": "…", "choiceId": "…" }`.
- Construction: `{ "kind": "sentence_assembly", "itemId": "…", "tileIds": ["…", "…"] }`; every supplied tile must occur once.
- Explicit skip: `{ "kind": "skip", "itemId": "…", "reason": "not_sure" }`.

Record presentation even when the learner never answers that question: both `response` and `submittedAtMs` are null. Such a question must be the final observation. Questions never presented have no observation. A learner who advances without an answer must explicitly skip; missing rows cannot be filled with invented skips.

The validator checks exact form order, item/response identities and revisions, permitted option IDs, complete tile permutations, monotonic presentation/submission times and the absolute deadline. Responses at the twenty-minute deadline are rejected, matching production. Completed sessions require every form item to have a response; time-limit sessions require exactly 1,200,000 elapsed milliseconds. Withdrawal may occur earlier. Skips count as responses, not attempted answers.

Each participant, session and reference-evidence UUID must occur once across the input collection. There is one session per participant. Combine the study's records into one validated collection before fitting; separate invocations cannot detect a person reused under another UUID or in another file. Keep any identity/evidence mapping outside the repository and response file. The format is pseudonymous, not a guarantee of anonymity. It accepts no names, email addresses, recordings, free-text responses or marking comments. It checks the declared reference method/date/identifier structurally; it cannot verify certificates, classify learners or verify the study protocol's contents from a supplied hash.

## Descriptive report

`inspectJapanesePilot` validates before using the existing Japanese grader. It reports:

- Study, protocol, bank and forms identifiers; participant counts by split and independently declared reference band; completion/timeout/withdrawal counts.
- Overall and per-item assigned, presented, attempted, correct, incorrect, explicit-skip, presented-unanswered and unreached counts.
- Per-item, per-reference-band cells separately for development and holdout. `correctRate` divides correct answers by attempted answers; `correctIncludingSkipsRate` divides by attempted answers plus skips. Missing/unreached questions enter neither denominator. A zero denominator returns null.
- Mean presentation-to-submission milliseconds over submitted answers and skips; unanswered time is censored and is excluded from that mean. Timings are supplied collection-runner observations, not trusted production server timestamps.
- Aggregate option selection counts and nominal uniform guessing baselines. Choices use `1 / options`; constructions use accepted visible orders divided by distinct visible tile permutations, accounting for identical displayed tiles. These arithmetic baselines are not fitted guessing parameters.
- Missing reference/holdout bands, unobserved items and items with no attempted answers. Missing coverage stays visible instead of being replaced with synthetic successes/failures.

The report excludes participant/session/evidence UUIDs and does not produce learner levels. It always returns `status: descriptive_only`, `fittedModel: null`, `publicationReady: false`. It does not claim item discrimination, statistical precision, equal form difficulty or calibrated likelihoods from descriptive rates.

## What remains before fitting and publication

Specify the actual study protocol: independent Japanese reference criteria (including below N5), evidence recency/verification, participant recruitment and form allocation, exclusions, sampling/precision targets, participant-level development/holdout allocation, timing capture and treatment of incomplete sessions. The current allocator and data schema do not decide these study requirements or establish that a JLPT pass is an exact reading/writing ability label.

Then collect independently levelled Japanese learner evidence in a controlled runner using these forms, validate the combined collection and inspect content, skips, timing, distractors and construction-order behavior. Fit the six-band likelihoods only from suitable evidence; evaluate discrimination, uncertainty and level interpretation on held-out learners. Model fitting, uncertainty/precision analysis and production adaptive-path timing validation remain future work. No sample-size or accuracy threshold has been invented in this increment.

Content/rights checks and digest-bound placement validation still govern publication of the reusable bank. None introduces teacher marking, individual response review before a lesson, recordings or free-text writing.
